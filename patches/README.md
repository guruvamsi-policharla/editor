# patches/

Core patches against VS Code. They're applied by VSCodium's `prepare_vscode.sh` from its `patches/user/` directory, after all of VSCodium's patches. `fork/scripts/prepare-vscodium.sh` copies them there. Base: VS Code 1.135.0 @ `08d4889f` plus the VSCodium patches at the ref in `fork/upstream.env`.

| Patch | Purpose |
|---|---|
| `90-diff-preserve-short-matching-lines.patch` | Two new diff options, both off by default so upstream behavior is unchanged. `preserveShortMatchingLines`: don't join hunks separated by short unchanged lines. `alignSimilarLines` (new file `alignSimilarLines.ts` + tests): pair an edited line with its old version even next to inserted or deleted lines, and make those lines a change of their own when an unchanged line can separate them |
| `91-chat-editing-review-hooks.patch` | `ChatEditingTextModelChangeService`: the external-edit predicate gets the content-change event (C3), plus public `extendToSubwords` / `preserveShortMatchingLines` fields (C4). Navigate actions are enabled by `agentReview.isActive` as well as chat (C5). Entries that set `hunkToolbarRows` (agent review) get each hunk's Keep/Undo toolbar in its own row below the hunk instead of over its first line. The "cursor in a change" context key (Ctrl/Cmd+Y / Ctrl/Cmd+N on a hunk) is per editor and set only by the integration of the file the editor shows. Agent-review wording and the "Agent Review" palette category for the review commands, the diff title and the explorer tooltip (Keep/Undo and keybindings unchanged). Track changes for hunks that also insert or delete whole lines; Ctrl/Cmd+Y/N act on the change at the cursor; the file overlay at the bottom center with the file's name, and not in the 3-way merge editor (agent review only). fix-1: the user's edits are mirrored into the original exactly (the rebase dropped an AI insertion at the offset where the user typed, so later keystrokes landed in the wrong place, #15); text typed inside a pending change is tracked (`userTextIn`) so the change's Undo can ask; Keep/Undo recompute a diff that is older than the models instead of applying stale ranges; the agent-review overlay's "n of m" counts the file's own changes (#13); agent-review lines, words and deleted rows carry classes of their own for the high contrast styles (#19) |
| `92-agent-review.patch` | New `src/vs/workbench/contrib/agentReview/` (entry, service, contribution, save-attribution participants, 3-way merge for agent writes under unsaved edits, CSS, tests) plus its import in `workbench.common.main.ts`. Readable copies are in `fork/src/`, and CI checks that they match. fix-1: the entry's state is derived from its diff (#16); Undo of a change with the user's typing in it asks first (#15); high contrast styles (#19) |
| `93-default-layout.patch` | Secondary side bar hidden by default (it hosts the agent chat, opened on demand), and 420 px wide (a third of the window at most) instead of 300 px when first shown, so the chat's pickers fit |
| `94-agent-chat.patch` | For the agent-chat extension. New `src/vs/workbench/contrib/agentChat/` (readable copy in `fork/src/`) with two internal commands: `_agentChat.insertReference(text, uri, range)` puts a Cmd/Ctrl+L reference at the chat input's cursor as an inline pill, after any pill the caret is inside, and a longer insertion no longer deletes the previous pill (core's dynamic variable, as `#selection` does; the request gets it as a `Location` reference with its offset in the prompt), and `_agentChat.openChat(uri, where)` opens a chat session in the side bar or an editor tab (Search Chats). Those pills aren't repeated as attachment chips. The sessions list resolves extension-contributed session types while `chat.disableAIFeatures` is on (Copilot's own types stay hidden). Stop moves an extension's open tool cards (external tool invocations) to Cancelled, so a command card no longer keeps its spinner after Stop (test in `chatModel.test.ts`). fix-1: a session type that lists its own commands offers only those and the ones registered for it in the slash list (`chatInputCompletions.ts`); the sent message doesn't repeat Cmd/Ctrl+L pills as file cards (`chatListRenderer.ts`); a selected model re-published under the same id with a new name is shown by the new name (`chatInputPart.ts`). Pre-launch: text typed or pasted inside a pill turns it into plain text and keeps every character; the decoration doesn't always grow with an insertion inside it, and deleting its stale range left a fragment such as `4` (#23, `chatDynamicVariables.ts`, tests in `chatVariables.test.ts`). The pickers under the chat input wrap onto a second row in a narrow chat instead of cutting their labels short (#37, `chat.css`) |
| `95-welcome-page.patch` | The welcome page shows no upstream content: VS Code's built-in walkthroughs ("Get started with …", "Learn the Fundamentals") aren't registered (extensions' walkthroughs still are), the announcements list from VSCodium's patch fetches nothing (VSCodium's feed is about VSCodium) and isn't shown while empty (#38). Made with `git diff -U1` so no branded line (VSCodium in a stale tree, Editor in CI) is in its context. Also the three ESLint warnings in VSCodium's announcement code, which `lint-core.sh` now checks |

**Regenerating:** in a prepared tree, reverse-apply our patches (`git apply -R patches/9*.patch`, last one first) and commit that state as a base. Re-apply the patches, make your edits, then run `git add -N src/vs/workbench/contrib/agentReview` and `git diff HEAD -- <paths> > patches/9x-….patch`. Copy the new files back into `fork/src/`. CI's `patches` job checks that the series applies and that the patched tree typechecks.
