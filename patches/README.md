# patches/

Core patches against VS Code. They're applied by VSCodium's `prepare_vscode.sh` from its `patches/user/` directory, after all of VSCodium's patches. `fork/scripts/prepare-vscodium.sh` copies them there. Base: VS Code 1.135.0 @ `08d4889f` plus the VSCodium patches at the ref in `fork/upstream.env`.

| Patch | Purpose |
|---|---|
| `90-diff-preserve-short-matching-lines.patch` | Two new diff options, both off by default so upstream behavior is unchanged. `preserveShortMatchingLines`: don't join hunks separated by short unchanged lines. `alignSimilarLines` (new file `alignSimilarLines.ts` + tests): pair an edited line with its old version even next to inserted or deleted lines, and make those lines a change of their own when an unchanged line can separate them |
| `91-chat-editing-review-hooks.patch` | `ChatEditingTextModelChangeService`: the external-edit predicate gets the content-change event (C3), plus public `extendToSubwords` / `preserveShortMatchingLines` fields (C4). Navigate actions are enabled by `agentReview.isActive` as well as chat (C5). Entries that set `hunkToolbarRows` (agent review) get each hunk's Keep/Undo toolbar in its own row below the hunk instead of over its first line. The "cursor in a change" context key (Ctrl/Cmd+Y / Ctrl/Cmd+N on a hunk) is per editor and set only by the integration of the file the editor shows. Agent-review wording and the "Agent Review" palette category for the review commands, the diff title and the explorer tooltip (Keep/Undo and keybindings unchanged). Track changes for hunks that also insert or delete whole lines; Ctrl/Cmd+Y/N act on the change at the cursor; the file overlay at the bottom center with the file's name, and not in the 3-way merge editor (agent review only) |
| `92-agent-review.patch` | New `src/vs/workbench/contrib/agentReview/` (entry, service, contribution, save-attribution participants, 3-way merge for agent writes under unsaved edits, CSS, tests) plus its import in `workbench.common.main.ts`. Readable copies are in `fork/src/`, and CI checks that they match |
| `93-default-layout.patch` | Secondary side bar hidden by default (it hosts the agent chat, opened on demand), and 420 px wide (a third of the window at most) instead of 300 px when first shown, so the chat's pickers fit |
| `94-agent-chat.patch` | For the agent-chat extension. New `src/vs/workbench/contrib/agentChat/` (readable copy in `fork/src/`) with two internal commands: `_agentChat.insertReference(text, uri, range)` puts a Cmd/Ctrl+L reference at the chat input's cursor as an inline pill (core's dynamic variable, as `#selection` does; the request gets it as a `Location` reference with its offset in the prompt), and `_agentChat.openChat(uri, where)` opens a chat session in the side bar or an editor tab (Search Chats). Those pills aren't repeated as attachment chips. The sessions list resolves extension-contributed session types while `chat.disableAIFeatures` is on (Copilot's own types stay hidden). Stop moves an extension's open tool cards (external tool invocations) to Cancelled, so a command card no longer keeps its spinner after Stop (test in `chatModel.test.ts`) |

**Regenerating:** in a prepared tree, reverse-apply our patches (`git apply -R patches/9*.patch`, last one first) and commit that state as a base. Re-apply the patches, make your edits, then run `git add -N src/vs/workbench/contrib/agentReview` and `git diff HEAD -- <paths> > patches/9x-….patch`. Copy the new files back into `fork/src/`. CI's `patches` job checks that the series applies and that the patched tree typechecks.
